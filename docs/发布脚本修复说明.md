# 每日发布脚本修复（2026-10-23）

## 原因

- 本机 `python` 命中 WindowsApps 的商店占位程序，`cmd /d /c "python --version"` 返回 9009；安装的 Python 3.11.5 可由 `py -3` 正常启动。
- 旧脚本在提交成功、推送失败后，再运行遇到 `nothing to commit` 就退出，无法补推已有提交。
- Git 失败没有统一返回非零退出码，`git add` 结果未检查，缺封面仍继续，可能误报成功。

## 修复

- 批处理优先验证并使用 `py -3`，其次验证 `python`；要求 Python 3.10+，不修改系统 PATH。
- 使用批处理自身目录定位仓库，固定 UTF-8；只在批处理暂停一次，并保留真实退出码。
- `.gitattributes` 为批处理固定 CRLF，避免检出后发生命令拆行问题。
- 默认日期为 Asia/Shanghai；支持指定日期补发、无副作用预检。
- 缺草稿、重复日期、缺封面、错误标签或图片日期不匹配时停止。
- Git 使用参数列表而非 shell 拼接；失败即停止。先 fetch，仅允许快进同步，不再自动 stash/rebase 或失败后继续。
- 只提交选中文章和封面；发现无关暂存文件、无关待推送提交或分支分叉会停止，不覆盖不同的正式内容。
- 无新变更时仍可重试已有文章提交的 push；比较远程 master 与本地 HEAD，确认远程收录后才报告成功。GitHub Actions 部署成功仍需另行验收。

## 发布时发现的 CI 版本漂移

首次推送的 Code quality 工作流使用 `version: latest`，实际下载 Biome 2.6.2，导致大量未修改源码被判定为格式不符。本地及独立 `pnpm dlx @biomejs/biome@2.4.14 ci ./src` 检查均通过（仅既有的 2 条警告与 1 条提示）。因此仅将工作流版本固定为与 `package.json`、`pnpm-lock.yaml` 一致的 2.4.14，不修改检查规则、不格式化既有源码。

## 用法（PowerShell）

```powershell
# 双击同样执行默认的今日发布；此命令会提交、推送并触发部署。
& 'D:\blog\Firefly_zureeallv\发布今日文章.bat'

# 只检查，不复制、不提交、不推送、不联网。
& 'D:\blog\Firefly_zureeallv\发布今日文章.bat' --dry-run

# 指定过去日期补发；也可同时使用 --dry-run。
& 'D:\blog\Firefly_zureeallv\发布今日文章.bat' --date 2026-10-20

# 隔离临时仓库测试，不访问生产远程。
Set-Location 'D:\blog\Firefly_zureeallv'
py -3 -m unittest discover -s scripts -p test_publish_today.py -v
```

批处理默认保留 `pause`；非交互调用可设置环境变量 `PUBLISH_NO_PAUSE=1`，或直接运行 `py -3 publish_today.py`。推送失败会保留文章与提交，修复网络或权限问题后用相同日期重试；脚本不会自动修改认证设置。
